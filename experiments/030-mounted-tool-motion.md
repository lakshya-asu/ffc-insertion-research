# 030 — Mount the CAD tool and commission empty motion

The commercial-actuator CAD is now part of the official FR3 articulation in Isaac Sim. A fixed flange attachment and two physical prismatic joints replace the prescribed group transforms used by the earlier CAD animation. No cable, PCB or camera-guided task controller is present in this commissioning scene.

[Watch the mounted motion and inspect the traces](https://lakshya-asu.github.io/ffc-insertion-research/hardware/custom-gripper.html#mounted-motion) · [Seven-step project status](../SEVEN_STEPS.md)

## Assembly and coordinate contract

`src/ffc/hybrid_tool.py` reads CAD revision 004. All 47 component surfaces remain visible. The orange sensor reservation has no mass/collision contribution and is not presented as a working sensor. Tool bodies are fixed frame, deployment carriage (including deployment shaft) and lower jaw (including clamp shaft).

The provisional adapter is a 60 × 60 × 14 mm aluminium envelope contacting the top of the backbone. Its top sits at the existing link8 flange plane, 107 mm from link7. A 180° rotation about flange X orients the authored tool toward the work surface in the commissioning pose. Bolt holes, retention, wrench access and stiffness are unqualified. This adapter is generated by the Isaac scene module; the older standalone CAD downloads do not contain it.

The articulation exposes the seven FR3 revolute joints, `deploy` in metres from 0 to 0.020, and `clamp` in metres from −0.020 to 0. Negative clamp position means positive actuator extension. A stowed jaw has both joint coordinates zero. Lowering the parked jaw uses −0.018 m; deployment uses +0.018 m; the nominal closed reference uses −0.008 m. Those positions express geometry, not acceptable cable pinch forces.

Only initial joint positions/velocities are assigned directly. All recorded movements then use position/velocity drive targets and measured joint feedback. The cameras are human observation views. Simulator object state is not an input to this controller; collision reports are independent experiment-validity checks.

## Declared approximation level

This is a rigid-body mechanism model with assumed actuator behavior. It is not yet a realistic calibrated PQ12 or cable model.

- Payload: **0.46957 kg**. Solid volumes use assumed densities (metal 2,700, printed 1,240, soft 1,100, purchased bearing/cup envelopes 7,800 kg/m³). Each PQ12 contributes 19 g, split 16 g body / 3 g shaft. These assignments, including treating all authored metal as aluminium and purchased envelopes as steel, are approximations. Part inertia uses a bounding box with that mass and the parallel-axis theorem. Hoses, electronics and a real sensor cartridge are absent.
- Drives: 8,000 N/m stiffness, 80 N·s/m damping, 5 N force cap, 8 mm/s velocity cap. These are explicit commissioning assumptions, not identified hardware parameters or safe contact-force limits.
- Collision shapes: per-component convex hulls plus adapter. Directly connected bodies have joint-level collision filtering to avoid filled guide/bearing holes blocking their intended slide. This excludes some physically relevant internal contact; retain the CAD audit and qualify actual running fits separately. Self-collision is not globally disabled on the arm.
- Physics: 1 ms timestep, gravity, PGS; existing FR3 drive assumptions retained. A bounded integral correction offsets static gravity error. The revised controller suppresses accumulation into clipped position-target limits; it does not model effort saturation, backlash, gearbox friction or a potentiometer.
- No pressure/seal model, cable contact, pad compliance, load-cell path, motor electrical dynamics or thermal model. The accelerated cycle does not enforce or qualify the actuator's 20% maximum duty cycle.

The nominal closed CAD gap is 0.14 mm. It cannot be treated as a force-control setpoint. The new larger tool does not inherit the old Pi scene's visibility/clearance results.

## Tests and gates

A quintic reference commands stop-to-stop arm moves, then lower → deploy → close → open → withdraw → stow. The joint feedback—not elapsed time alone—must satisfy the endpoint gate before the sequence advances.

| Check | Bound used for this experiment |
|---|---|
| Arm reference step | At most the requested amplitude, capped at 0.1 rad |
| Arm reference velocity / acceleration | 0.025 rad/s / 0.02 rad/s² |
| Measured arm speed | 0.03 rad/s |
| Arm tracking after first 0.5 s of phase | 0.02 rad |
| Measured tool speed | 8.1 mm/s |
| Tool tracking after first 0.5 s | 1 mm |
| Tool travel overrun | At most 0.1 mm beyond authored limits |
| Endpoint arm error / speed | 0.0002 rad / 0.001 rad/s |
| Endpoint tool error / speed | 0.15 mm / 0.1 mm/s |
| Settling deadline | Nominal phase duration + 4 s |
| Cancel excursion | 0.001 rad arm; 0.25 mm tool |
| Physics clock | Callback count equals commanded steps; renders advance zero physics time |

Cancellation replaces the moving reference with a hold reference and then verifies measured settling. It is not a hardware protective stop. The contact audit retains existing unloaded-test thresholds and reports all observed pairs. No absence-of-contact result establishes a clearance margin.

## Development evidence

`mounted-tool-probe-001` passed the initial headless 33.009 s cycle. `mounted-tool-probe-002` recorded the same sequence with separate arm/tool units and tighter tool gates: 825 frames, 6.75 mm/s peak tool speed, 0.386 mm peak transient tracking error, no reported contact pairs. The first mounted shoulder cancellation and deployment cancellation also passed.

The trace exposed integral accumulation at the clamp's zero-travel limit. Although it passed the deliberately broad commissioning gate, it delayed the next move. We added conditional integration at clipped position targets and regression tests covering both limits, direction reversal and ordinary gravity correction. The final cycle and cancellation evidence use the same revised controller. Earlier runs remain in `outputs/`; the public matched bundle contains the final reports and traces.

**Final cycle (`mounted-tool-probe-003`):** PASS; 44,009 physics steps / 44.009 s; 1,100 frames at 25 fps; full 0.1 rad shoulder move and return plus all six mechanism transitions. Peak tool tracking error 0.02054 mm, peak tool speed 6.75082 mm/s, peak arm speed 0.02501 rad/s. No contact pairs were reported. These are model results, not a hardware accuracy claim.

**Final cancellations:** mounted-arm-cancel-002 PASS, 7.002 s, post-cancel arm excursion 0.00004080 rad. mounted-tool-cancel-002 PASS, 14.755 s, post-cancel tool excursion 0.0066 mm. Both use the revised controller; both reported no contact pairs.

See `docs/hardware/mounted-tool/review.json` for selected run IDs, source hashes, artifact hashes and frame ledgers. The video is rendered from actual physics states. It is not playback of the earlier CAD transforms.

## Reproduce

Prerequisites: local CAD revision 004, pinned official FR3 asset, and the existing `ffc-isaac:6.1.0` image. Pause the live preview and wait for it to exit first. Use fresh output directories, and check `results.json` rather than relying on the Isaac process exit code.

```bash
docker compose -f compose.yaml run --rm experiment scripts/isaac_joint_probe.py \
  --tool /workspace/outputs/hybrid-tool-cad-004 --joint 2 --amplitude .1 \
  --output /workspace/outputs/mounted-tool-cycle-NEW

docker compose -f compose.yaml run --rm experiment scripts/isaac_joint_probe.py \
  --tool /workspace/outputs/hybrid-tool-cad-004 --joint 2 --amplitude .1 --case cancel \
  --output /workspace/outputs/mounted-arm-cancel-NEW

docker compose -f compose.yaml run --rm experiment scripts/isaac_joint_probe.py \
  --tool /workspace/outputs/hybrid-tool-cad-004 --case tool-cancel \
  --output /workspace/outputs/mounted-tool-cancel-NEW

.venv/bin/python design/hybrid-tool/publish_motion.py \
  --cycle outputs/mounted-tool-cycle-NEW \
  --arm-cancel outputs/mounted-arm-cancel-NEW \
  --tool-cancel outputs/mounted-tool-cancel-NEW
```

The publisher rejects failing reports, mismatched controller/geometry revisions and frame ledgers inconsistent with the physics clock. Inspect encoded videos and the page as additional publication checks. Restore the native ROS preview afterwards.
